- **Problem**: 클라이언트가 `successUrl?amount=100`으로 조작 시 9,900원 결제가 100원으로 승인될 위험. PG사 confirm API를 서버에서 호출하되 금액을 클라이언트 파라미터가 아닌 DB에서 조회해야 함
- **Action**: `validateConfirmRequest({ queryAmount, dbAmount, dbStatus })` 순수 함수 설계 → 금액 불일치·이중 승인·0원·음수 등 7개 케이스 vitest 작성 → 성공 시에만 Toss confirm API 호출, 실패 시 payments.status=failed 기록
- **Result** (수치 포함): 금액 변조 방어 로직 vitest 7/7 통과, 멱등성(success URL 중복 접근) 처리 포함. "보안 로직은 순수 함수로 분리해 테스트" 원칙 적용

## 소재 1: LLM 채점 비결정성 해결 (2026-06-11)

- **Problem**: AI 문서 품질 채점을 심판 LLM에 일임하니 같은 입력에서 누락률이 11.1%↔0%로 널뜀 — 분모(핵심 정보 개수)를 매번 다르게 세서 프롬프트 버전 비교가 불가능
- **Action**: 정답 문서를 원자적 사실 체크리스트로 1회 변환·캐시해 분모를 고정하고, 심판은 항목별 yes/no 판정만(temperature 0), 집계는 순수 함수로 분리
- **Result** (수치 포함): 3회 반복 채점에서 누락 항목까지 100% 동일 재현. 버전 간 A/B 비교 기반 확보

## 소재 2: 네거티브 테스트로 평가 시스템 결함 사전 검출 (2026-06-11)

- **Problem**: 채점 시스템이 "전부 통과"를 내도 판별력이 있는지 알 수 없음 — 검출 못 하는 채점기는 무의미
- **Action**: 일부러 핵심 섹션을 삭제하고 가짜 사실을 주입한 결함 문서로 검출력 테스트 → 심판이 트랜스크립트를 근거로 누락을 존재 판정하는 참조 혼동 결함 발견 → 판정 기준을 프롬프트에 명시 고정
- **Result** (수치 포함): 주입한 결함 3건(누락 2 + 환각 1) 100% 검출. 결함을 운영 투입 전 발견

## 소재 3: 골든셋 반복 비용 최적화 (2026-06-11)

- **Action**: 샘플×버전 단위 캐시를 비교 파이프라인에 내장해 변경된 버전만 재호출, 채점 분모(체크리스트)도 1회 생성 후 재사용
- **Result** (수치 포함): 동일 비교 재실행 시 API 호출 40회 → 0회, 신규 버전 추가 시 절반만 호출

## 소재 4: 환각 금지 원칙과 AI 추론 보완의 양립 — 라벨 정책 설계 (2026-06-11)

- **Problem**: 제품 1원칙이 "영상에 없는 내용 생성 금지"인데, 포지셔닝 확장(매장·현장직)으로 "설명이 서툴러 생략된 절차를 AI가 채워달라"는 상충 요구 발생
- **Action**: "라벨 없는 추론"만 환각으로 재정의 — 스키마에 inferred 필드, 에디터 [AI 보완]+작성자 확인 동선, 채점은 환각 제외+별도 집계로 정책·UI·평가 3계층 일관 설계. 추론 범위는 절차 단계로 한정
- **Result** (수치 포함): 스키마 v2 전환 후 누락률 3.7%→0% (동일 체크리스트 27개), 환각 0건 유지. "환각 0" 지표의 의미를 희석하지 않고 보완 기능 도입

## 소재 6: 업무 유형 추론 기반 누락 감지 — LLM 자기 평가 루프 설계 (2026-06-12)

- **Problem**: 보강 질문 생성기가 "문서 내 빈 섹션" 기반이라 섹션 자체가 없는 누락(현금 거스름돈 처리, 근무 물품 보관 위치)을 감지 못함 — 채점은 걸리는데 질문은 안 나오는 평가 불일치
- **Action**: 3단계 분석 구조로 재설계 — ① 문서에서 업무 유형 추론(매장 판매직/사무직 등) → ② 직종별 필수 인수인계 항목 내부 체크리스트 생성 → ③ 문서와 비교해 없는 항목만 질문화. 기존 빈 섹션/절차 비약 감지는 후순위로 유지
- **Result** (수치 포함): 거스름돈 처리·안경 보관 위치 2건 모두 질문으로 자동 생성 확인. 질문 수 5~7개로 확대해 coverage 향상

## 소재 7: ffmpeg 네이티브 바이너리 Next.js 번들링 문제 해결 (2026-06-12)

- **Problem**: 영상 업로드 시 `spawn #ROOT\node_modules\ffmpeg-static\ffmpeg.exe ENOENT` — 바이너리는 존재하는데 실행 불가
- **Action**: 경로 로그 추가로 런타임에 `#ROOT` 플레이스홀더가 찍히는 것 확인 → Next.js webpack이 `import("ffmpeg-static")` 번들링 시 바이너리 경로를 플레이스홀더로 치환함을 진단 → `serverExternalPackages: ["ffmpeg-static"]` 1줄로 번들 제외
- **Result** (수치 포함): 33MB 영상 → ffmpeg mp3 추출 성공, STT 파이프라인 진입 확인. 수정 범위 `next.config.ts` 1줄
