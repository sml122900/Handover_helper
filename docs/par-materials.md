# 이력서 소재 모음 (PAR)

> Problem(문제) — Action(행동) — Result(결과) 형식으로 기록.

## 소재 1: LLM 채점 비결정성 해결 (2026-06-11)

- **Problem**: AI 문서 품질 채점을 심판 LLM에 일임하니 같은 입력에서 누락률이 11.1%↔0%로 널뜀 — 분모(핵심 정보 개수)를 매번 다르게 세서 프롬프트 버전 비교가 불가능
- **Action**: 정답 문서를 원자적 사실 체크리스트로 1회 변환·캐시해 분모를 고정하고, 심판은 항목별 yes/no 판정만(temperature 0), 집계는 순수 함수로 분리
- **Result** (수치 포함): 3회 반복 채점에서 누락 항목까지 100% 동일 재현. 버전 간 A/B 비교 기반 확보

## 소재 2: 네거티브 테스트로 평가 시스템 결함 사전 검출 (2026-06-11)

- **Problem**: 채점 시스템이 "전부 통과"를 내도 판별력이 있는지 알 수 없음 — 검출 못 하는 채점기는 무의미
- **Action**: 일부러 핵심 섹션을 삭제하고 가짜 사실을 주입한 결함 문서로 검출력 테스트 → 심판이 트랜스크립트를 근거로 누락을 존재 판정하는 참조 혼동 결함 발견 → 판정 기준을 프롬프트에 명시 고정
- **Result** (수치 포함): 주입한 결함 3건(누락 2 + 환각 1) 100% 검출. 결함을 운영 투입 전 발견

## 소재 3: 골든셋 반복 비용 최적화 (2026-06-11)

- **Problem**: 프롬프트 버전 비교는 샘플 10개 × 버전 2개 = LLM 호출 40회 — 반복 개선 루프의 비용·속도 병목
- **Action**: 샘플×버전 단위 캐시를 비교 파이프라인에 내장해 변경된 버전만 재호출, 채점 분모(체크리스트)도 1회 생성 후 재사용
- **Result** (수치 포함): 동일 비교 재실행 시 API 호출 40회 → 0회, 신규 버전 추가 시 절반만 호출
