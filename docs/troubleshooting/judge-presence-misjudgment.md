# 심판 LLM이 누락을 0건으로 오판 (presence 판정 기준 혼동)

## 문제상황
체크리스트 채점 판별력 검증을 위해 네거티브 테스트를 수행: AI 문서에서 계정·관계자 섹션을
통째로 삭제하고 가짜 사실("구독자 100만 명")을 주입. 환각은 정확히 1건 검출됐지만,
**삭제된 섹션에만 있던 사실들이 전부 present(존재) 판정** — 누락률 0%로 나옴.

## 시도한 것들
1. 체크리스트 항목 확인 → 계정 이메일(fact 12), 백업 문의처(fact 15)는 삭제된 섹션에만 존재. 누락이어야 맞음
2. 심판 입력 재검토 → 심판에게 AI 문서 "주장 목록" + 트랜스크립트 + 정답 문서를 함께 제공하는 구조.
   프롬프트의 판정 1("AI 문서에 존재하는가")에서 "AI 문서"가 무엇인지 명시하지 않음
3. 가설: 심판이 컨텍스트에 있는 트랜스크립트/정답 문서에서 사실을 찾고 present=true로 판정 (참조 대상 혼동)

## 최종 해결법
judge 프롬프트에서 판정 기준을 명시 고정:
- "**AI 문서의 전체 내용은 아래 '주장 목록'이 전부입니다**" 선언
- "트랜스크립트나 정답 문서에 있다는 이유로 true 판정 금지 — 그것들은 판정 2의 근거 자료일 뿐" 명시
- evidence에 주장 번호 인용 요구 (검증 가능하게)

수정 후 재실행: 삭제된 사실 2건(critical 계정 이메일 포함) 정확히 누락 검출. 누락률 7.4% (2/27).

## 교훈
- LLM 심판에게 여러 텍스트를 주면 "어느 텍스트 기준 판정인지"를 반드시 명시해야 한다
- "전부 통과" 결과는 판별력의 증거가 아니다 — 일부러 망가뜨린 입력으로 검출력을 먼저 증명할 것

## 이력서 소재 한 줄
LLM 기반 품질 평가 시스템에 네거티브 테스트(결함 주입)를 도입해 심판의 참조 대상 혼동 결함을 출시 전 발견,
프롬프트 판정 기준 고정으로 누락 검출 정확도를 회복 (0% 오판 → 주입 결함 100% 검출).
