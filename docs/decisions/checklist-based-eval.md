# 체크리스트 기반 LLM 채점 선택 이유

## Problem
AI 변환 품질 채점(누락률·환각)을 심판 LLM에 통째로 맡기니 결과가 비결정적이었다.
같은 샘플·같은 프롬프트인데 누락률이 11.1% ↔ 0%로 널뜀 — 심판이 "정답의 핵심 정보 개수"(분모)를
매번 다르게 세기 때문. 분모가 흔들리면 프롬프트 v1 vs v2 비교가 무의미해진다.

## Action
LLM의 재량을 "항목별 판정"으로만 좁히고 계산을 코드로 옮겼다.
1. 정답 문서를 원자적 사실 체크리스트(JSON)로 1회 변환·캐시 → **분모 고정** (`npm run checklist`)
2. 심판(temperature 0)은 ① 체크리스트 사실이 AI 문서에 존재? yes/no+인용 ② AI 문서 주장별 근거 있음? yes/no — 판정만
3. 누락률·환각 집계는 순수 함수(`lib/ai/eval-core.ts`)가 결정적으로 계산, 판정 누락 시 throw
4. 네거티브 테스트(고의 결함 문서)로 판별력 검증

## Result
- 3회 반복 채점에서 누락 항목까지 **완전 동일** (7.4%, 2/27, 환각 0 × 3회)
- 네거티브 테스트: 삭제한 사실 2건(critical 포함)·주입한 가짜 사실 1건 정확 검출
- 검증 과정에서 심판 결함 1건을 출시 전 발견·수정

## 대안과 트레이드오프
- 임베딩 유사도 매칭: LLM 호출 없이 저렴하나 "의미 동일·표현 상이"(마스킹, 문어체 변환) 판정 불가
- 정답 문서를 그대로 비교: 자유 형식 markdown이라 기계 대조 불가 → 체크리스트가 중간 표현 역할
- 비용: 샘플당 체크리스트 1회 호출 추가 — 캐시로 1회성, 분모 신뢰성과 맞바꿈
