# AI 보완(inferred) 라벨 정책 — 환각 금지 원칙과의 양립

## Problem
제품 포지셔닝이 매장·현장직·알바 인수인계로 확장되며 새 요구가 생김:
설명이 서툰 전임자가 명백히 생략한 절차 단계(예: 포스기 정산 후 시재 확인)를
AI가 채워줘야 문서가 실용적이다. 그러나 "트랜스크립트에 없는 내용 금지"는
제품의 1원칙 — 무단 보완을 허용하면 환각과 구분할 수 없게 된다.

## Action
"추론 자체"가 아니라 "라벨 없는 추론"을 환각으로 재정의했다.
1. 스키마: 절차 단계에 `inferred: boolean` 필드. 추론 보완 시 true + confidence
   needs_review + sourceTimestamp null 강제 (프롬프트 규칙)
2. 에디터: inferred 항목은 `[AI 보완] … — 작성자 확인 필요` 하이라이트 — 작성자
   확인 동선이 needs_review와 동일해 별도 UI 불필요
3. 채점: inferred 주장은 환각 집계에서 제외하되 `inferredClaims`로 별도 보고 —
   "환각 0건" 지표의 의미를 유지하면서 추론량을 투명하게 추적
4. 범위 한정: 절차 외 섹션 추론 금지, 새 사실(이름·숫자·위치) 창작은 inferred여도 금지

## Result
- sample-handover 재변환·재채점: 누락 3.7% → 0.0%, 환각 0 유지 (동일 체크리스트 27개)
- 환각 정의가 "근거 없음 + 라벨 없음"으로 검증 가능해짐 (vitest로 집계 로직 고정)

## 대안과 트레이드오프
- **전 항목에 inferred 허용**: structured output grammar 한도 초과(400)로 불가했고,
  원칙상으로도 "생략된 단계" 보완이라 절차 한정이 요구사항과 일치
  (→ troubleshooting/structured-output-grammar-limit.md)
- **추론을 본문이 아닌 보강 질문으로만 처리**: 환각 리스크 0이지만 문서가 미완성으로
  남음 — 대신 enrich-v2가 inferred 항목 확인 질문을 생성해 이중 안전망
- **inferred를 채점에서 환각으로 카운트**: 정책상 허용한 동작을 벌점화하면 프롬프트가
  보완을 회피하도록 학습됨 — 별도 집계로 분리
