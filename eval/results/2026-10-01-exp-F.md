# 실험 F 컨텍스트 방식: RAG vs 매장 원문 전체 (2026-10-01)

> 판정은 채택이 아니라 비교 보고다: 현재 규모에서 어느 쪽이 나은가, 몇 배부터 역전되는가.

## 설정

- **RAG**: 현 기본값(충분성 노드 분리, 검색 상위 5개 + 재검색 1회). 실험 G 확인 실행이 사전 기준 미충족이라 통합 노드가 아닌 **기준선 3회**(09-30 생성, 보완 기준 v2·안정화로 재채점, 재실행 없음)를 쓴다. G 확인 실행(RAG 통합 노드)은 참고 열로만 싣는다
- **전체 컨텍스트**: 질문 경로에서 검색 없이 매장 원문 전체(기본 청킹 문서 + 트랜스크립트 청크, 원문 순서, 마스킹, 매장당 약 9천~1만 토큰)를 시스템 프롬프트 뒤 캐시 블록(5분 TTL)으로 넣고, 답변 노드 1회가 답변 가능 판정과 답변을 함께 낸다(실험 G 통합 프롬프트 재사용). 답할 수 없으면 재검색 없이 에스컬레이션. 시각·도구·범위 밖 경로는 RAG와 같다. 3회(10-01 생성, 실행 1→2→3 연속이라 실행 2·3은 캐시 쓰기 0)
- 채점: 보완 기준(v2)·안정화(2회 + 엇갈리면 3회째 다수결). **근거 충실도의 근거가 조건마다 다르다**: RAG는 받은 청크, 전체 컨텍스트는 넣어 준 원문 전체(지시대로). 출처 일치는 전체 컨텍스트에서 인용된 근거만 채점기에 준다
- 비용: Claude 실측(캐시 쓰기 1.25배·읽기 0.1배 반영) + 같은 호출을 캐시 없이 보냈다고 가정한 값. 교차점은 사실 20문항 × 배수별 1회(1배 = 전체 컨텍스트 실행 1 재사용, 2배·5배 = 다른 매장 원문을 표시 없이 덧붙임, 약 1.7만·4.1만 토큰)

## 해석 (Claude Code) — 비교 보고, 채택 판정 아님

- **현재 규모(1배, 매장당 약 9천~1만 토큰)에서는 전체 컨텍스트가 모든 측정 지표에서 RAG 기준선 이상**이다: 답변 정확도(주) 11.0 → 13.0(쌍별 +3·+3·+0), 근거 충실도 위반 6.3 → 5.7, 거절 10/10 유지, 질문당 비용 -31%(도구 문항 제외 -38%), 지연 p50 13.2 → 8.8초, **p95 22.0 → 12.1초**(목표 8초는 여전히 미달). 사전 기준을 둔 판정 실험이 아니고 3회라 정확도 +2는 "차이 있음"으로 단정하지 않는다(기존 개선 기준 3쌍 모두 +2 이상에는 못 미침)
- 이득의 상당 부분은 **답변·판정 통합(실험 G와 같은 구조)**에서 온다: 같은 통합 구조의 RAG(G 확인 실행)와 비교하면 정확도 13.3 vs 13.0으로 비슷하고, 전체 컨텍스트 쪽이 비용 -30%($0.0245 → $0.0171, 도구 제외)·p50 -1.1초·p95 -6.2초. p95 차이는 문서에 없음 문항에서 RAG가 재검색 경로(재작성 + 재검색 + 재판정)를 타는 반면 전체 컨텍스트는 바로 에스컬레이션하기 때문이다
- **비용 이점은 캐싱 덕분이다**: 캐시가 없다고 가정하면 전체 컨텍스트가 1배에서 이미 RAG보다 비싸다($0.0347 vs $0.0249). 캐시 적중 질문만 보면 $0.0172. 실행 1(콜드)에는 매장마다 첫 질문에 캐시 쓰기(약 1만 토큰 × 1.25배)가 들어가 $0.0192
- **교차점(사실 20문항, 1회씩)**: ① 비용 — 캐시 적중 기준 약 **4.5배**(약 4만 토큰)에서 RAG($0.0261)와 같아진다. 이번 실측(20문항 중 매장마다 첫 질문이 캐시 쓰기)으로는 **약 1.3배**에서 이미 역전 — 매장별 질문이 5분 안에 몇 번 이어지느냐(캐시 적중률)가 교차점을 정한다 ② 지연 — 5배까지 p50 10.6 → 11.0초로 거의 늘지 않아 측정 범위 안에서 역전 없음(RAG 13.2초) ③ 정확도 — 문항 완전 11 → 11 → 10, 정답 사실 13 → 13 → 12로 소폭 하락, 5배에서 다른 매장 근거 인용 1건. 근거 충실도 위반이 4 → 3 → 2로 주는 것은 채점 근거(넣어 준 원문 전체)가 커지는 정의 효과일 수 있어 개선으로 읽지 않는다
- **결론(제안: Claude Code)**: 지금 코퍼스 규모(매장당 1만 토큰 미만)와 질문이 매장별로 몰리는 사용 패턴이라면 전체 컨텍스트 + 캐싱이 RAG보다 싸고 빠르며 정확도도 낮지 않다. 매장 문서가 약 4~5배(4만 토큰 안팎)로 늘거나 매장별 질문 간격이 캐시 TTL(5분)보다 길어지면 비용에서 RAG가 유리해진다. 지연은 5배까지 전체 컨텍스트가 유리했다. 기본값 변경은 사용자 결정(결정: 대기)
- **한계**: ① 기준선 RAG는 09-30, 전체 컨텍스트는 10-01 실행 — 지연에 날짜·동시 실행(교차점 실행·채점과 동시) 차이가 섞인다 ② 근거 충실도 정의가 조건마다 다르다(위 설정) ③ 교차점은 다른 매장 원문을 표시 없이 덧붙인 가혹 조건이며(의도적 겹침 절차 포함) 1회·20문항이다. RAG는 매장 필터로 검색 범위가 변하지 않는다고 보고 상수로 두었다(같은 매장 문서가 늘어나는 경우의 RAG 재현율 변화는 미측정) ④ 1배 실행 1의 s1은 사전 점검(2문항)으로 캐시가 데워진 상태였다 ⑤ 전체 컨텍스트 3회는 연속 실행이라 실행 2·3의 캐시 쓰기가 0 — 실제 서비스의 적중률은 트래픽에 달렸다

## 결정 (이성민, 2026-10-01)

- **기본값 RAG 유지.** 비용 이득(-31%)은 캐시 적중 전제이고 캐시 없이는 전체 컨텍스트가 더 비싸다($0.0347 vs $0.0249). 실제 매장은 질문 간격이 길어 캐시 만료가 잦을 수 있다
- 캐시 유효시간(Anthropic 공식 문서 Prompt caching, 2026-10-01 확인): 기본 5분, 쓸 때마다 추가 비용 없이 갱신 / 연장 1시간(`"ttl": "1h"`) / 단가 배수: 5분 쓰기 1.25배, 1시간 쓰기 2배, 읽기 0.1배
- 손익분기(이번 실측 단가로 계산한 추정): 5분 TTL이면 한 매장에서 5분 안에 질문 약 4개 이상, 1시간 TTL이면 매장당 시간당 약 8개 이상이어야 RAG보다 싸다
- 지연 이득은 캐시와 무관한 단일 호출 구조에서 온다(p50 13.2 → 8.8초, p95 22.0 → 12.1초) — 별도 기록
- 결론: **코퍼스가 작고 질문이 짧은 간격으로 몰리면 전체 컨텍스트가 유리, 문서가 누적되거나 질문 간격이 길면 RAG가 유리.** 규모·트래픽 기반 자동 선택은 다음 단계 후보로만 기록
